# RPEN 视频渲染模块

唯一用户入口为顶部右侧 `#render-video`“渲染”按钮；在谱面库首页禁用，不增加卡片动作、侧栏、工具栏或快捷键入口。UI、场景和编码模块按需动态加载，不注册模组，也不使用全局 DOM MutationObserver。

## 数据和时间

`src/application/render-project.mjs` 从当前谱面捕获只读副本和素材引用。普通谱面采用完整 chart；超大谱面采用完整磁盘文档的 header、revision、区间 window、hits 和 soundNames。窗口不作为完整数据源，不展开重合组。磁盘 revision 改变时明确终止，不能继续混用两个版本。

画面、音符、打击音效和输出区间均使用**谱面秒**。音乐位置 = 谱面秒 + 有效 offset / 1000。修改面板中的偏移只改变音乐读取位置，不移动音符与打击音效。音乐时长扣除偏移后用于自动终点；明确的 `META.duration` 优先。无音乐时遍历音符、普通与特殊事件、噪域、全局事件的实际时间字段，排除遥远的状态延续哨兵时间。

窗口接口 `soundNames` 返回当前磁盘文档的去重音效名（包含 tap/drag/flick），最多 512 种，用于预先解码和计算音效尾音范围。`hits` 是谱面秒、半开区间，返回的 count 为实际重合数量。混音按 count 加权，不创建 count 个对象，不使用整段 8192 次截断。

## 参数和皮肤

`schemas/video-render-settings-v1.schema.json` 描述本机偏好。设置不写入谱面，不进入谱面撤销。区间打开时重置；其他偏好持久化于 `rpen-render-studio-v1`。任务开始时冻结参数，禁用参数表单，并独立创建最终分辨率的场景。实时预览的分辨率与输出分离，最大 1280×720。

`skinPolicy` 默认为 `render`：渲染器控制打击粒子，保留所选皮肤的音符和命中贴图。`skin` 尊重皮肤自身的粒子隐藏、时长、尺寸、旋转和着色规则。全局关闭打击特效仍优先；皮肤信息不会写回或临时污染编辑器共享记录。音效优先级为谱面同名素材、所选皮肤、内置声音；不借用编辑器的旧皮肤缓存。

默认渲染策略的打击粒子采用 PR #34 的参数：扩散半径系数 `1.1×0.85×1.3×1.03`、尺寸系数 `0.0907×1.05`，寿命 `2/3` 秒、数量 4；外扩采用 `render-particles.mjs` 的有理函数，透明度为 `1-progress`，从寿命的 40% 开始按 sine-in 收缩，幅度 `0.253×1.15`（29.095%）。命中贴图仍以音符尺寸的 1.4 倍绘制，默认 31 帧、每帧 0.015 秒，资源包动画沿用所选皮肤。渲染面板预览与视频导出共用这些参数，普通编辑器播放和 `skin` 策略沿用各自原有特效。保留现有完整命中枚举及批绘制，不引入模组旧版的固定数量截断。

打击特效与普通播放共用 `Preview.drawHits` 的命中枚举、位置缓存、视口裁剪和 GPU 批绘制。`render` 仅提供粒子外观、完整寿命及保守绘制半径；`skin` 直接沿用普通播放的皮肤特效路径。密集区间不按固定总数量截断特效，避免旧粒子占满名额、遗漏后续新打击；视口裁剪不得遗漏边缘仍可见的贴图或粒子，批绘制失败回退 Canvas 路径。

噪域在普通预览与视频渲染中共用 `previewNoiseGeometry`：中心按舞台横纵比例适配，角点相对中心先旋回局部坐标、按自身横纵轴缩放、再旋回，保持旋转角和矩形形状。之后再执行 `NoisePreview.transformGeometry`（如三维摄像机投影），不覆盖已有钩子；窗口外复用已变换几何时不重复缩放。噪域取样的轮廓、角点及事件值反算使用同一显示变换，锚点仍表示绝对舞台坐标；谱面本体的事件、积分及坐标语义不变。

`render-studio/noise.mjs` 只在渲染实例上启用 `NoiseSkinRenderer` 的 `overlay:true`，并为未指定皮肤的噪域层补入内置 NoiseField；补入信息仅保存在缓存的渲染副本，已有皮肤优先，不写入原谱面。overlay 保留一张原始场景纹理，计算皮肤结果与原图的 RGB 最大通道差，用 `smoothstep(0.003,0.022,delta)` 作为混合权重，再以预乘透明度叠加；小色差效果会被削弱。普通编辑器预览保持默认 `overlay:false` 的整帧替换，不使用颜色差过滤，也不自动补入默认皮肤。

## 编码与输出

Mediabunny 1.65.0 为未修改的官方 npm 浏览器模块，固定版本、来源、源码提交和校验值见 `assets/vendor/mediabunny/UPSTREAM.json`，MPL-2.0 及源码取得地址随程序分发。

`src/platform/video-encoder.mjs` 在逐帧前等待数据和资源就绪，按固定帧率写入，末帧缩短至所选区间终点。音频按最多一秒的 PCM 块混合，跨块保留音效尾部，按时间与视频交错写入；不分配整段离线混音或整段压缩视频缓冲。所选容器无法编码预期音频时明确失败，不能自动变为无音轨视频。

`src/application/render-frames.mjs` 负责跨平台帧调度。`CanvasSource.add` 同步捕获当前画布后，仅允许下一帧的绘制与当前帧编码重叠；下一次送帧仍须等待编码器和文件输出的背压，不累积帧队列。缺少同步 `VideoFrame` 快照能力时自动采用顺序绘制。分辨率、帧率、编码质量、所有帧时间戳、音效与混音算法保持相同；不通过改变编码器质量模式加速。

编码任务的 `drawFrame(time,index,frames,signal)` 只负责准备和绘制输出画布；独立的 `onFrame` 回调提供实际编码画布，面板预览和进度按墙钟最多约每 100 ms 更新一次（首尾必更新），不减少文件中的输出帧。不重复复制另一套试听画布。主线程按时间片协作让出：支持时使用 `scheduler.yield`，否则使用定时任务；Shader 的资源等待以实际截止时间判断，避免更快的任务调度造成假超时。取消或错误时中止并收回提前绘制，再释放场景。

桌面桥 `rpenRenderOutput` API 1 只向当前受信主窗口公开 `begin/write/close/commit/abort/openFolder`。begin 显示保存对话框，返回不可猜测的 token；write 为有界随机位置写入（每次最多 1 MiB）；close 刷盘但不覆盖原文件；commit 完成后原子切换。成功保存后，面板右下角显示“打开所在文件夹”；openFolder 只接受当前窗口最后一次成功保存的 token，由主进程打开记录中的目标父目录，不接受任意路径。打开失败明确提示原因。失败和取消删除任务临时文件，保留旧目标。导航、渲染进程退出或窗口关闭清理任务及已完成 token；每个窗口最多保留一个已完成结果。路径由原生对话框选择，不能由 write 请求指定。

网页优先使用 File System Access，缺省使用 OPFS 临时文件；不会退回整个文件的 BufferTarget。OPFS 结果发起下载后可再次下载，关闭时清理临时文件。网页仅报告“已发起下载”，不声称浏览器文件已落盘。输出选择取消、编码取消、保存失败和保存成功分开报告。

## 渲染扩展和清理

`src/ui/render-extensions.mjs` 提供 `registerRenderExtension(attach)`。attach 接收新预览器和 purpose（`autoplay` / `export`），返回幂等释放函数。三维摄像机复用此入口；原有两个编辑器实例保持原行为。渲染也调用 `preview:before` 和相应覆盖层，回调必须使用传入的 chart/seconds，离线导出不依赖实际播放头。

`Preview.dispose()` 解绑字体监听，释放批绘制、Shader 与噪域资源以及辅助画布。加载和渲染分别有 AbortSignal、代次和最终清理；关闭后不接受过期结果。静止关闭面板无采样、无播放循环。待渲染的音乐或音效缺失/解码失败必须有明确原因，不静默导出残缺声音。

实际能力依设备的 WebCodecs 编码器而异；能力探测不代替各平台实测。
