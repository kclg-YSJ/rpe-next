# 谱面版本控制

“谱面工具 → 版本控制”打开右侧临时页面，包含提交图、更改、分支、储藏和引用日志。首次打开自动建立初始提交。已有项目会保存版本库标识，不要求为此修改谱面；新建或导入后尚未保存的谱面须先保存到谱面库，才能在重新打开时关联相同的历史。

## 快照和保存

一个快照包含谱面 JSON、素材字节、素材路径、空文件夹和谱面 JSON 文件名。文件按内容哈希去重。先“暂存”再“提交”可记录当前快照；分支、标签和提交图属于版本库，与编辑器撤销栈独立。提交历史不会自动覆盖谱面库，手动保存也不会自动生成版本提交。自动保存继续创建恢复副本。

检出、重置、合并或应用储藏会暂停播放并重新载入快照，结果标为未保存，仍需保存到谱面库。当前编辑会话与撤销栈会重新建立；模组应处理现有的 `editor:chart` 通知并刷新引用。软重置只移动版本库引用，混合重置还更新暂存区，硬重置另将快照载入编辑器。改动冲突、校验或写入失败时不应移动 HEAD 并提交损坏结果。

## 合并约定

使用共同祖先、当前分支与目标分支进行三路合并。单侧修改直接采用，独立字段修改组合，不能确定的修改显示“当前 / 对方”冲突选项。判定线优先按两侧唯一名称识别，再使用唯一的内容对应处理改名；重名且无法确定身份时要求选择整个谱面，避免猜测对应关系。互不相容的重排显式要求选择排列顺序。

父线和内置根级 shader 的线号会先转换为临时身份，待冲突选择、删线和顺序确定后再恢复最终编号。删除的父线解除绑定，删除所属线的 shader 不会改绑到其他线。临时身份只用于算法，不改变谱面结构，也不写入谱面文件。提交合并前检查谱面结构及父线索引、循环关系；产生循环时保留原分支，用户修改对应分支后重试。

谱面中未知字段与模组数据会保留，但通用 JSON 合并不能推断未知字段的含义。自定义线号引用、插件资源及字段间约束需要模组提供校验或自定义合并。接口接入和钩子范围见[模组协议](MOD-PROTOCOL.zh-CN.md#62-谱面版本控制)。

## 存储和备份

网页端历史位于当前站点的独立版本数据库。桌面端历史保存在所选原生谱面库的 `version-repos`、`version-commits`、`version-trees`、`version-blobs` 中，素材仍由谱面库按内容去重。桌面“备份完整库到文件夹”和搬迁包含这些记录；切换库也切换其版本历史。

普通 JSON、PEZ 和谱面库 PEZ 合集导出的是作品内容，不附带版本历史；需要单独迁移历史时，在版本控制页导出仓库包。网页端清除站点数据会同时清除本地版本历史，应保留仓库包或其他外部备份。

## 仓库包 v1

仓库包为 JSON，`format` 为 `rpe-next-chart-vcs`，`version` 为 `1`。根对象包含导出时间 `exportedAt`、版本库引用与配置 `repo`、提交数组 `commits`、树数组 `trees` 和二进制对象数组 `blobs`。每个二进制对象以 `[内容哈希, Base64字节]` 存储，树记录谱面对象哈希、素材对象列表、文件夹与谱面文件名；提交记录树、父提交、作者、时间、说明和操作种类。包内的项目作者名称、邮箱和所有可达历史素材会随包导出。

导入校验二进制和树的内容哈希、必要引用及已有对象的一致性，不覆盖内容不同的同名对象。导入到当前仓库时重建提交身份，重名分支和标签生成独立名称；导入不会自动检出或覆盖当前编辑。此格式是版本控制数据，不是谱面格式，不通过修改 `RPEVersion` 表达。

规范化、差异、合并和内容校验保留 JSON 的所有自有字段，包括 `__proto__`、`constructor`、`prototype` 等名称；这些名称始终作为数据处理。冲突路径只遍历自有属性，写入与删除不会访问原型链；分支和标签名称也遵循相同的自有属性规则。

累计编辑秒数 `rpeNextEditTime` 属于谱面工作元数据，保存、备份和谱面导出携带；版本树与差异忽略它，避免仅因时间流逝产生内容提交，检出旧版本也不回退本机累计时间。

## 皮肤入口

编辑器皮肤可用 `@version-control-tool` 重排入口，用 `@version-control-panel` 设置面板样式；页面名为 `version-control`，可通过 `data-rpen-pane` 定位状态。这是皮肤 API 3 的兼容扩展，原有皮肤继续有效。
